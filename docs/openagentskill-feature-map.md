# OpenAgentSkill 功能机制映射

更新日期：2026-08-22。本文只映射公开产品机制，不复制 OpenAgentSkill 的品牌、文案、排序分数、视觉资产或私有实现。公开证据来源：[首页](https://www.openagentskill.com/)、[Skills 目录](https://www.openagentskill.com/skills)、[任务目录](https://www.openagentskill.com/tasks)、[Skill Packs](https://www.openagentskill.com/skill-packs)、[提交页](https://www.openagentskill.com/submit)、[API 文档](https://www.openagentskill.com/api-docs)。

## 核心判断：兼容“发现与安装”，但产品重心放在“工作流诊断与真实运行”

OpenAgentSkill 的公开形态重点是注册表：把自然语言任务解析成 Skill 候选，展示质量、维护、信任、风险和兼容性信号，再给出复制或安装交接。Skillflow 应直接兼容这套必要的供给侧与发现能力，但不能止步于目录；我们的增强层是把用户的真实工作拆成节点、解释每个节点是否适合 AI、组合多个 Skill、在人工批准门后真实运行，并用交付物和运行回执证明价值。

| 公开功能机制 | Skillflow 决策 | MVP 实现要求 | 边界 |
| --- | --- | --- | --- |
| Skill 元数据：名称、摘要、作者、分类、标签、仓库、版本、许可证、平台兼容性 | 直接兼容并增强 | 继续使用 canonical manifest；增加输入/输出 Schema、执行控制、权限、适用/不适用场景、证据等级、版本和商业许可内部级别 | 外部作者与许可证必须保留原始归属；许可证分级暂不在公开网站展示 |
| Skill 详情页 | 直接兼容并增强 | 展示功能 brief、输入输出、适用/不适用、限制、权限、版本、作者、许可证来源、样例输入、样例输出、评测证据和运行入口 | 没有真实运行证据时必须标 E0，不展示虚构成功率 |
| 搜索与筛选 | 直接兼容并增强 | 支持 Skill 名、自然语言任务、工种、行业、场景、交付物、软件、数据源、风险、平台兼容性筛选 | 大众一级导航不用 MCP、Agent、Plugin 等实现术语 |
| Task-to-Skill Resolve：任务输入、主推荐、备选、原因、风险、安装计划 | 直接兼容并增强 | 返回一个主方案、最多两个备选、适用原因、不适用条件、权限/连接需求；若单 Skill 不足，直接返回工作流方案 | 推荐分数必须可解释并区分公开信号与真实运行证据 |
| 排名与趋势 | 暂缓公开榜单，保留数据结构 | 先按任务适配、风险、许可证可用性、中文办公适配、维护状态和评测证据排序 | Star、浏览和新鲜度只能当注意力信号，不能等于真实质量 |
| 信任与安全审计 | 直接兼容并增强 | 安装前展示权限、网络、凭据、外部动作、风险提示和沙箱要求；MVP 不运行任意第三方脚本 | 审计只能说明发现的风险，不能承诺绝对安全 |
| Copy / Install | 直接兼容但 MVP 分两级 | instruction-only Skill 可复制 SKILL.md 或生成目标平台安装说明；第三方代码型 Skill 只生成审查清单和人工安装交接，不在平台执行 | MVP 不自动执行 `npx`、Shell 或任意仓库脚本 |
| Packs / 组合包 | 增强为可编辑 Workflow | 不只按角色给静态包；把用户工作流拆成节点，每个节点绑定 Skill、输入输出合同、审批点和替代方案 | Pack 是供给模板，用户的 workflow 才是执行实例 |
| Compare | 直接兼容并增强 | 对比任务适配、输入输出、权限、模型/连接器、证据等级、维护、成本延迟和替代关系 | 不用一个总分掩盖风险或能力不匹配 |
| Submit：仓库、目录或 SKILL.md 链接；先入队、异步审核 | 直接兼容 | 支持 URL 导入、上传 SKILL.md、自然语言创建；保存草稿后做格式、来源、许可证、安全和评测审核 | 提交成功不等于推荐或可执行；作者身份需单独验证 |
| 创作者资料与归属 | 直接兼容并增强 | 保留作者名、原始仓库、原许可证、版本历史；支持用户发布自创 Skill 和后续收益归属字段 | 当前全部免费，分润和定价只留数据结构，不在 MVP 上线 |
| Agent API：搜索、详情、resolve、install、receipt | 兼容式建设 | 网站与 AI 客户端共用同一份 Skill/Workflow 契约；先提供搜索、详情、resolve 和运行回执 | API 返回必须与人类界面一致，避免双套排名逻辑 |
| JSON 与 text 两种机器可读格式 | 暂缓 text，保留 JSON | MVP API 以 JSON 为唯一合同；后续为 Agent 增加紧凑 text 格式 | 不应为了节省 token 损失权限、风险和证据字段 |
| 运行结果与 outcome feedback | 直接兼容并增强 | 每次真实运行记录成功/失败/需要设置/风险阻断、输出质量、人工复核、模型、耗时和 token；同任务可复现 | 自报 outcome 与平台评测必须分开标注，不能混成“成功率” |
| Evals 与安装回执 | 直接兼容并增强 | 每个 Skill 带测试夹具和质量规则；工作流运行前生成计划回执，运行后生成节点级回执 | E0 是定义完成，E1 是内部夹具，E2 才是沙箱真实运行；没有证据不能升级 |
| 自动发现 GitHub Skill | 暂缓 | 先人工抓取和审核互联网产品/运营领域高价值开源 Skill，再建设定时发现管线 | 抓到仓库不代表可商用或可执行，必须经过许可证和风险分级 |

## MVP 优先级：先让七个节点真的跑通

第一优先级不是扩大 Skill 数量，而是完成“访谈材料标准化 → 证据抽取 → 洞察聚类 → 工作流 AI 适用性判断 → 人工确认 → PRD 生成 → 确定性质量检查”的端到端真实运行，并让每个模型输出通过 JSON Schema、引用校验和人工批准门。其中第四步必须逐节点回答“是否应使用 AI、如何组合 Skill、AI 做什么、人做什么、如何验收”，不能只给一份笼统洞察。第二优先级是把同一组真实 Skill 放进目录、详情、搜索、复制和工作流推荐页面，证明“单 Skill 直接使用”和“组合工作流运行”共享同一供给合同。第三优先级才是开放提交、作者工作台、排行榜、自动抓取和商业化。

## 状态定义：直接兼容、增强、暂缓不能混用

“直接兼容”表示产品需要提供等价的用户能力和机器合同；“增强”表示在等价能力上增加工作流诊断、节点组合、真实运行或证据回执；“暂缓”表示数据模型可以预留，但在黄金工作流跑通前不投入完整界面和运营资源。这一区分可以防止再次出现页面很多、真实可用能力很少的空壳。
